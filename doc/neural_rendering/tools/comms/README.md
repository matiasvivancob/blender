# Comms scripts

`post.sh` / `watch.sh` (bash, Linux and Git Bash) and `post.ps1` / `watch.ps1` (PowerShell 5.1 or 7, Windows) do the same two jobs from `PROTOCOL.md` with the GitHub CLI: `post` writes one `[result]`, `[question]`, `[review]` or `[blocked]` comment on the coordination PR, with the branch and short commit hash in its header, and `watch` prints PR comments you have not seen yet and fast-forwards the branch when `origin` has new commits (`--ff-only`, never a rebase). Install and log in once with `winget install GitHub.cli` then `gh auth login`; the scripts use `NEURAL_PR_REPO` (default `matiasvivancob/blender`) and `NEURAL_PR_NUMBER` (default `1`), and `watch` keeps its list of seen comment ids in `NEURAL_WATCH_STATE` (default `$HOME/.cache/neural_pr_watch` for the shell script, `%LOCALAPPDATA%\neural_pr_watch` for the PowerShell one). Commit and push first, then post from inside the checkout: `python doc\neural_rendering\tools\buildbox\check_env.py --out env.md; .\doc\neural_rendering\tools\comms\post.ps1 result "Build box environment" env.md`, or pipe the text in (`... check_env.py | .\post.ps1 result "title"`); `.\watch.ps1` does one pass and `.\watch.ps1 -Loop 300` repeats every five minutes. If PowerShell refuses to run the scripts, use `powershell -ExecutionPolicy Bypass -File .\post.ps1 ...` or `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. The `.ps1` files could not be run where they were written (no PowerShell there), so the first real post is also their first test; `watch.ps1` reads the comments as one JSON object per line, so multi-line comment bodies are kept intact.
